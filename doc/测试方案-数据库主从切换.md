# 数据库主从切换功能测试方案

## 一、环境准备

### 1. 安装两个 SQL Server 实例

在同一台机器上安装两个 SQL Server Express 实例（或用两台机器）：

- **主库**：`.\SQLEXPRESS`（默认实例，你现在用的）
- **从库**：`.\SQLEXPRESS2`（新装一个命名实例）

安装步骤：
1. 下载 SQL Server Express：https://www.microsoft.com/sql-server/sql-server-downloads
2. 安装时选「新建 SQL Server 实例」
3. 实例名填 `SQLEXPRESS2`
4. 认证方式选「混合模式」或「Windows 身份验证」

### 2. 初始化从库

打开 SSMS 连接到 `.\SQLEXPRESS2`，手动创建数据库：

```sql
CREATE DATABASE IsolationLeakageDb;
```

然后运行同步脚本做一次完整同步（把主库数据复制过去）：

```powershell
.\tools\SyncDatabase.ps1 -PrimaryServer ".\SQLEXPRESS" -SecondaryServer ".\SQLEXPRESS2"
```

### 3. 配置应用

启动软件 → 系统管理 → 数据库高可用 → 配置主从切换：

- 勾选「启用数据库故障切换」
- 从库地址填：`.\SQLEXPRESS2`
- 点「测试连接」→ 成功
- 健康检测间隔：`5`（测试时改短一点，正式用 15）
- 失败重试次数：`2`
- 切回等待时间：`10`（测试时改短一点）
- 点「保存」

## 二、测试用例

### 测试 1：正常启动 ✅

**操作**：直接启动软件

**预期结果**：
- 左下角状态指示灯显示「主库 / 正常 / .\SQLEXPRESS」
- 系统管理 → 数据库高可用 → 显示「主库 / 正常 / 已启用」
- 所有功能正常使用

---

### 测试 2：主库故障自动切换 ✅

**操作**：
1. 软件正常运行中
2. 打开 Windows「服务」管理器（services.msc）
3. 找到 `SQL Server (SQLEXPRESS)` 服务 → 右键「停止」

**预期结果**：
- 5~15 秒后，左下角状态指示灯变为「从库 / 从库运行 / .\SQLEXPRESS2」（橙色）
- 系统管理 → 数据库高可用 → 显示「从库 / 从库运行」
- 日志文件（logs/目录）中出现：`主库连续 2 次连接失败，执行故障切换到从库`
- 软件功能恢复正常（读写从库）

**检查日志**：
```
logs/app-xxxx.log 中应包含：
- "主库连接失败（第 1/2 次）"
- "主库连接失败（第 2/2 次）"
- "执行故障切换到从库"
- "已切换到从库: .\SQLEXPRESS2"
```

---

### 测试 3：主库恢复自动切回 ✅

**操作**（接测试 2）：
1. 当前在从库运行中
2. 回到 Windows「服务」管理器
3. 找到 `SQL Server (SQLEXPRESS)` 服务 → 右键「启动」

**预期结果**：
- 等待 10~30 秒（切回等待时间 + 确认次数 × 检测间隔）
- 左下角状态指示灯变回「主库 / 正常 / .\SQLEXPRESS」（绿色）
- 日志中出现：`主库已恢复且稳定...准备切回` → `已切回主库`

---

### 测试 4：数据缓冲不丢失 ✅

**操作**：
1. 软件在「实时监视」页面，PLC 正在采集数据（或用模拟数据）
2. 停止主库 SQL Server 服务
3. 等待自动切换到从库
4. 切换到从库后，检查实时曲线数据是否完整

**预期结果**：
- 切换空窗期内采集的数据被缓冲到内存
- 切换到从库后，缓冲数据自动补写到从库
- 实时曲线不出现断档

**检查日志**：
```
logs/app-xxxx.log 中应包含：
- "数据库写入失败，数据将缓冲"
- "缓冲区刷新完成：成功 X/Y"
```

---

### 测试 5：启动时主库不可用，自动从从库启动 ✅

**操作**：
1. 先停止主库 SQL Server 服务
2. 启动软件

**预期结果**：
- 不弹出数据库配置对话框
- 直接从从库启动
- 左下角显示「从库 / 从库运行」
- 日志中出现：`主库不可用，自动切换到从库启动`

---

### 测试 6：主库和从库都不可用 ✅

**操作**：
1. 同时停止两个 SQL Server 服务
2. 启动软件

**预期结果**：
- 弹出数据库配置对话框
- 对话框内有远程连接说明
- 用户可以选择输入新的服务器地址

---

### 测试 7：远程连接（WiFi/局域网）✅

**前提**：需要另一台机器（或虚拟机）

**操作**：
1. 在机器 A 上装 SQL Server，运行软件
2. 在机器 B 上通过 WiFi 连接同一网络
3. 在机器 A 的 SQL Server 配置管理器中启用 TCP/IP
4. 在机器 A 的防火墙中放行 1433 端口
5. 查看机器 A 的 IP 地址（ipconfig）
6. 在机器 B 上修改 appsettings.json：
   ```json
   "DefaultConnection": "Server=192.168.x.x\\SQLEXPRESS;Database=IsolationLeakageDb;..."
   ```
   或者在软件启动弹出配置对话框时输入 IP 地址

**预期结果**：
- 机器 B 上的软件通过 WiFi 成功连接机器 A 的数据库
- 所有功能正常

---

### 测试 8：配置保存和重载 ✅

**操作**：
1. 系统管理 → 数据库高可用 → 修改参数
2. 点保存
3. 关闭软件，重新启动
4. 再打开「数据库高可用」Tab 页

**预期结果**：
- 参数保持修改后的值
- appsettings.json 文件格式正确（没有 JSON 语法错误）

## 三、快速测试命令

如果不想手动操作，可以用 PowerShell 脚本快速模拟：

```powershell
# 停止主库（模拟故障）
Stop-Service "MSSQL`$SQLEXPRESS" -Force

# 启动主库（模拟恢复）
Start-Service "MSSQL`$SQLEXPRESS"

# 查看日志
Get-Content "logs\app-*.log" -Tail 30
```

## 四、注意事项

1. **从库数据同步**：测试前记得先运行一次 `SyncDatabase.ps1`，否则从库是空的，很多数据查不到
2. **同步频率**：正式环境建议每 1~4 小时同步一次（Windows 任务计划程序）
3. **同步冲突**：如果应用正在用从库（故障切换期间），不要运行同步脚本（会断开应用连接）
4. **测试环境隔离**：建议用独立的 SQL Server 实例测试，不要用生产数据库

## 五、常见问题

**Q: 为什么切换后从库上的数据不全？**
A: 从库是定期同步的，同步间隔内的新数据只存在于主库。切换后这部分数据需要等下次同步才能到从库。缓冲区会暂存切换空窗期的数据。

**Q: 切换过程中软件卡住了？**
A: 检查日志，可能是连接超时设置太长。可以在「数据库高可用」配置中把「连接超时」改短（如 3 秒）。

**Q: 从库启动后有些功能报错？**
A: 可能是因为从库上缺少某些数据（还没同步过来）。运行一次 `SyncDatabase.ps1` 同步数据即可。
